# DSH 0.1.2 工作台迁移设计

日期：2026-09-04

状态：已实现并验收

目标版本：DeepSeek Harness `0.1.2-rc.1`

## 1. 目标与边界

本次迁移保留 Contract Copilot 已验证的合同审查内核，包括 Python CLI、7 个 agent tool、九态 `SessionStore`、DOCX 修订与报告生成。改造范围集中在 DSH Web 工作台接入层，使插件使用当前公开组合接口并遵守浏览器会话认证。迁移后，律师仍以工作台作为主操作面，DSH session 保留为可追溯的审计与 agent 运转层。

本次同时把现有九态流程投影为四个用户可理解的阶段，并展示最近状态跃迁。逐条 finding 审批、后台 Agent 编排、多人协作和案件级批量队列不在本次范围，留给迁移后的产品化阶段。

## 2. 方案比较

### 方案 A：最小兼容补丁

只升级依赖与 Client Context 导入，继续轮询 `[data-slot=sidebar]` 并直接访问 `/contract-copilot/*`。优点是改动最少；缺点是依赖非公开 DOM，且自定义数据路由绕过 DSH 0.1.2 的浏览器会话认证。该方案只证明旧实现还能运行，不适合作为继续产品化的基础。

### 方案 B：受支持的 DSH 外壳迁移（采用）

入口注册到 `sidebar.footer.action`；JSON 操作经 `ctx.connection.rpc` 的认证通道传输；状态事件与 DOCX 下载注册到 Connection 的精确 Fetch 路由；Client 通过独立 API 适配器访问 Host。业务核心不变，UI 增加四阶段进度与最近操作轨迹。该方案消除当前安全缺口，同时保持 out-of-tree 插件的独立发布方式。

### 方案 C：完整 Typert Remote 与后台 Agent 工作台

把 ContractSession 提升为正式 Service Definition，生成 Typert Remote，增加 Client Controller，并由工作台直接创建后台 Agent 执行任务。长期一致性最好，但会把兼容迁移扩大为能力重构；当前 DSH 应用 Remote 选择仍是构建期集合，独立插件的接入成本明显更高。本次不采用，待工作台交互稳定后单独设计。

## 3. 架构与数据流

```text
sidebar.footer.action
        │
        ▼
ContractCopilotClient
   ├─ JSON 命令/查询 ── ctx.connection.rpc ──▶ Host SessionStore
   ├─ 状态事件 ─────── authenticated Fetch/SSE ─▶ SessionStore.subscribe
   └─ DOCX 下载 ───── authenticated exact Fetch ─▶ 本地产物文件

Agent tools ──▶ SessionStore ──▶ Python CLI ──▶ DOCX/报告
```

Host 在 Web profile 存在 `connection` 时注册工作台接口；headless profile 没有该服务时只保留 agent tools。所有浏览器请求先经过 Connection 的 Host/Origin 检查和签名 Cookie 认证。RPC 入口对 endpoint 与 payload 做显式校验；错误返回稳定的 `code/message/details`，Client 不再静默吞掉关键错误。

Client 入口不创建额外 DOM 节点，不轮询页面结构。Slot 注入 face 传入一个共享 `ContractCopilotClient`，React 组件只依赖该适配器。状态事件失败时保留十秒轮询兜底，避免短暂断线导致工作台失去更新。

## 4. 产品化投影

工作台把内部状态映射为四阶段：前置信息、审查分析、条款落地、交付归档。`created` 显示第一阶段待处理；`intake_done` 与 `plan_ready` 分别推进到分析阶段；`applying/applied/partial/rejected/failed` 落在条款落地；`delivered` 完成交付阶段。异常状态不伪装完成，保留原始状态标签。

右栏新增最近操作轨迹，直接展示 `historyTail` 中的 tool、起止状态与时间。这是当前不改 Python 前提下可可靠提供的最细粒度。逐 finding 的内部执行进度仍不可用，因为 Python CLI 在结尾前不输出阶段事件；若未来需要该能力，必须单独授权修改 Python 事件输出。

## 5. 验证

1. `pnpm run build`：Node 与 Client bundle 均能针对 DSH 0.1.2 依赖构建。
2. `pnpm run test`：9 个文件 80 项测试全绿，包括 RPC payload、认证路由、Client API 和隔离 Python spawn 集成测试。
3. 隔离 DSH profile 启动：插件能够装载，官方侧栏入口可见，工作台可打开。
4. 认证负向测试：无浏览器会话 Cookie 的 RPC、事件与下载请求返回 `401` 或 `403`，不再返回合同数据。
5. 浏览器烟测：session 列表、四阶段进度、文档视图、确认表单、下载入口和最近操作轨迹可见。

真实合同的 intake → analyze → apply → finalize 全链路沿用既有证据；本次若没有重新执行，应在交付时标为未重新验证。
